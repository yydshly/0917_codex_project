# 009 · Subtrace — 研究记录

## 2026-09-17：源码与静态展示

任务：新建子项目，以文档和网页说明能力与原理；不在 Windows 安装运行上游。

- 基准：`e3e3546b367ecc23d5fe5642491526ee969a6ff2`。
- 阅读：入口、seccomp、进程 / socket、TLS、HAR、发布及官方文档。
- 源码事实：seccomp 用户通知与 TCP 代理；出站 TLS 临时 CA；入站 TLS 回退；正文默认上限 4096 字节。
- 研究判断：降低后端网络排障的接入成本，不能直接归因业务函数内部耗时。
- 未验证：真实安装、TLS 兼容、容器权限、性能、服务端稳定性、完整私有部署。

## 演示约定

`/v1/orders`、`/v1/profile`、`/health`、`/v1/search` 是固定虚构样例。状态码、耗时、头部与正文是人工定义，没有真实目标服务，不发起实际请求，也不代表上游性能。

五种流程覆盖 HTTP、出站 HTTPS、入站 TLS、证书固定、未知 TCP。正文控件演示捕获副本截断；筛选控件不是 CEL 执行器。无外部依赖、分析脚本或远程 API；仅用户主动点击来源链接时离开研究页。

## 网页验证

构建、链接、交互和响应式结果见 [web-validation.json](experiments/web-validation.json)。全站构建与项目索引检查通过；Chromium 验证了 5 个场景各 5 步、前后步进与重置、请求搜索与筛选、空结果恢复、请求 / 响应 / 头部切换和 UTF-8 字节截断。320、390、768、1280、1440 像素宽度均无页面横向溢出，源码链接固定到研究版本，内部资源与文档链接可达。

同时检查了键盘展开详情、本地 file:// 阅读、禁用 JavaScript 后的正文，以及浏览器错误和外部请求记录，均通过。人工查看桌面、手机、流程、请求查看器和说明图截图，未见遮挡或文字重叠。该记录只针对本研究静态页面，不证明 Subtrace 实机能力。

未公开发布；元数据 `demo` 留空。

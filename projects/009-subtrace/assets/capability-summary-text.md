# Subtrace 能力与交互全景（文字版）

定位：给后端使用的 HTTP 网络调试器，观察被包装启动进程的请求与响应。

核心组合：seccomp BPF 筛选入口 + Go 用户态代理处理流量 + HTTP 记录与展示。

## 1. 控制路径：系统调用怎样被接管

`subtrace run -- my-server` 包装启动目标程序。目标程序调用 socket、connect、accept 等操作时，Linux 内核中的 seccomp BPF 过滤器判断是否需要接管。未匹配的调用直接放行；命中用户通知规则的调用线程等待 Subtrace 处理。

内核通过 seccomp 用户通知将调用交给 Subtrace 的 Go 进程。它读取参数与目标地址，管理 socket 与文件描述符，建立代理连接、注入描述符或返回结果。相关机制包括 pidfd、ADDFD 与进程内存读写。处理结果经内核返回，或者指示内核继续执行原调用，目标线程随后继续运行。

BPF 负责筛选入口，不承担 HTTP 解析、TLS 解密或界面展示。这不是通常所说的挂载 eBPF 探针被动抓包。

## 2. 数据路径：真实流量怎么走

以出站请求为例：目标应用 ⇄ Subtrace 本地 TCP 代理 ⇄ 真实外部服务。连接接管后，应用一般照常读写网络连接；无需每次读写都由 BPF 解析数据。

业务通信在目标程序、本地代理与外部服务之间双向传输。展示通道接收解析记录。

出站 HTTPS：临时 CA → 拦截已知 CA 文件读取并注入 → 两段 TLS 握手 → 代理内获取 HTTP 明文。应用 ⇄ 加密通道 A ⇄ 代理内明文 ⇄ 加密通道 B ⇄ 外部服务。证书准备与读取可早于连接，不代表逐请求时序；不覆盖磁盘系统证书。

入站 HTTP 同样经代理接入应用；未知 TCP 回退为原始字节复制。代理处于真实通信路径，因此有开销与兼容性成本。

## 3. 观察路径：从流量到浏览器

代理识别 HTTP 并解析为 HAR 记录，收集请求、响应、正文采样与时间信息，随后应用 CEL 规则。首条匹配规则决定是否保留记录；筛选记录并不阻断业务网络访问。

默认经 WebSocket 向 Subtrace 服务发布事件，供浏览器面板显示。另有本地 DevTools 展示路径，具体是否外联需结合 token 等配置检查。此路径传递观察记录，不是原业务请求的转发路径。

能力：方法、URL、状态、头部、正文采样、耗时；HTTP/1 与 HTTP/2；WebSocket 为实验功能。

边界：Linux 5.9+；Windows 原生不支持这条接管路径；入站 TLS 直接转发；证书固定 / mTLS 可能失败；该版本上游 TLS 证书校验不完整；默认正文 4096 字节；默认事件发布到 Subtrace 服务。不能直接解释业务函数内部耗时，未知 TCP 转发不等于全协议分析。

## 配置与画面的数据流

用户操作 → App.jsx 更新 config → scene.update(config) 更新材质和装配状态 → 每帧推进骑行状态、机构位置并渲染 → 约每 100 ms 将速度等读数回传 React。

这里有两类状态：config 表示用户选择，例如档位和刹车力度；ride 表示随时间演化的速度、距离和实际踏频。停止踩踏时仍有独立车速，因此可以表现惯性滑行。

React 负责面板，Three.js 对象保存在场景中。逐帧直接更新三维对象的位置、旋转及实例矩阵，不通过 React 重新创建整个模型。

## 三维模型如何生成

主体采用程序化建模，没有加载自行车 GLB / GLTF 模型文件：

- 车架、辐条和紧固件：圆柱体、圆环、球体、盒体按端点摆放，通过四元数将圆柱朝向对应连杆方向。
- 车把、把带、水壶架及座弓：曲线与 TubeGeometry 管状几何；把带接缝沿车把曲线螺旋生成。
- 飞轮、牙盘、链片和开孔坐垫：用 Shape 定义二维轮廓及孔洞，再用 ExtrudeGeometry 挤出厚度。
- 水壶：用 LatheGeometry 将半径轮廓旋转成实体。
- 手机屏幕：Canvas 2D 绘制离线导航图，再用 CanvasTexture 贴到三维平面上。

材质使用 MeshStandardMaterial / MeshPhysicalMaterial，涂装改变颜色、金属度、粗糙度和清漆。RoomEnvironment 与 PMREM 提供环境反射，方向光、半球光和阴影提供体积感。它们提高视觉真实感，但不会自动产生机械行为。

## 装配关系如何保证联动

scene.js 将整车分成 frame、drive、cockpit、frontWheel、rearWheel、saddle 六个 Group。配件挂在对应父节点下：

- 手机、铃铛与前灯属于 cockpit，跟随车把变换。
- 坐垫、座管与尾灯属于 saddle，一起升降或分解。
- 水壶架与座管快拆夹环属于 frame，留在车架上。
- 碟片属于旋转轮组，卡钳属于车架或前叉，所以卡钳不会跟着碟片转。

转向使用头管轴线的四元数旋转，前轮与前叉共享转向支点。分解视图改变装配组的位移；插值使变换平滑。相机同时补偿转向、分解和座椅升高的偏移，继续跟随被观察部件。

## 链条与变速

mechanics.js 负责计算，drivetrain.js 负责把结果显示出来。

1. 依据齿数和 12.7 mm 链条节距计算节圆半径：r = p / (2 sin(π / N))。
2. 用公切线连接牙盘、两个导轮和所选飞轮，再加上对应绕行圆弧构成闭合路径。
3. 以相邻销轴的三维直线距离推进布点，而不是简单按圆弧长度均分。当前链条为 122 节。
4. 通过二分调整后拨导板摆角，使整条链闭合；两个导轮的中心距保持 130 mm。直线段包含前后不同链线平面的横向偏移。
5. 链片、滚子、销轴分别使用 InstancedMesh，复用几何，通过每个实例的变换矩阵摆放；链片长度不随绕行半径缩放。

曲柄角速度由踏频决定，飞轮角速度由 54 / 后飞轮齿数的比例决定。切换 12 个档位会改变工作节圆、横向位置、后拨、齿片高亮及动力学目标速度。车速在切档瞬间保持连续。

边界：当前直接显示目标档位，没有跨齿片拨链过渡；齿形是示意轮廓，没有齿面接触、碰撞、张力和磨损求解。54T 前盘参与传动，40T 内盘仅展示。旧的 drivetrainCircles / fitChainLength 仍保留为基础路径工具，但当前链节渲染由 solveChain 的 122 节求解结果驱动。

## 刹车与惯性滑行

riding.js 保存车速、行驶距离、制动距离和运动模式，以不大于 1/120 秒的子步长推进教学模型。

- 目标速度：踏频 / 60 × 54 / 后飞轮齿数 × 2.133 m。
- 阻力减速度：R = 0.025 + 0.003v²，v 为 m/s。
- 前后刹归一化为 0–1，制动减速度为 4 × 前刹 + 2.5 × 后刹。
- 踩踏时有限加速至目标速度；滑行或制动时不再驱动链条，车轮按独立速度继续转动。
- 速度积分后限制为非负；距离按子步长内平均速度累计。

brakes.js 将刹车力度映射为两侧刹车片的对称位移，scene.js 同时转动握杆。减速和刹车片动画共享输入，但减速并不是由三维刹车片实际碰撞碟片计算出来的。

暂停冻结时间；慢动作缩放运动时间；单齿步进仅用于观察机构，不改变行驶速度。座管卡扣打开时也停止推进骑行。

功率读数采用 83 × R × v 的简化阻力功率估算，不包含加速所需功率。配置重量包含轮组和已安装配件，但不会反馈到当前动力学模型。没有坡度、轮胎抱死、侧滑、载荷转移或制动温升。

## 配件如何工作

| 能力 | 实现机制 | 边界 |
| --- | --- | --- |
| 车灯 | 发光材质 + 前方 SpotLight + 透明圆锥光束 | 光束方向示意，无照度与续航标定 |
| 座椅升降 | 沿座管轴向位移；UI 以卡扣状态限制滑杆 | 快拆手柄转动示意，无夹紧力求解 |
| 铃铛 | 拨杆衰减摆动 + Web Audio 两个振荡器合成音色 | 无录音采样或声学仿真 |
| 水壶取放 | 水壶子节点沿壶架方向平移并平滑过渡 | 壶架保持原位，取出不扣除携带重量 |
| 手机导航 | CanvasTexture 静态图 | 无地图服务、GPS 或路线计算 |
| 气流 | 随时间移动的 Line 几何 | 无 CFD；气动节省是轮组预设值 |

## 点击、视角与热点

OrbitControls 提供拖动旋转和缩放；预设视角保存相机位置与观察点，切换时插值过渡。点击模型时由 Raycaster 检测命中网格，向父节点查找部件标识，再打开对应配置。

热点是 HTML 按钮：每帧将部件三维位置投影到屏幕坐标。隐藏父节点内的部件不参与有效拾取，微观特写时隐藏热点以减少遮挡。

## 性能、测试与部署

- React 不驱动三维逐帧重建；链条复用实例几何，速度读数约 10 Hz 回传界面。
- 渲染像素比上限 1.75，帧间隔上限 50 ms；这能避免后台恢复时的大幅跳跃，但也意味着低帧率时模拟时间可能落后于墙上时钟。
- 材质切换复用现有对象；轮框切换释放被替换的几何；页面销毁时清理动画、监听、几何、材质及纹理。
- 当前 23 项自动测试覆盖路径、销距、变速比例、装配层级、制动、滑行和暂停等；测试通过不等同于真实机械仿真精度认证。
- Vite 使用相对资源路径打包，字体本地化。build.py 将静态客户端复制到 site/apps/010-veloce-bike-studio/，可作为静态网站托管。模板的可选 Worker 不进入该静态演示。

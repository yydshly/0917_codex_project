# 实际场景：一人启动 AI 办公短视频账号

[打开案例网页](../../../../site/apps/003-agency-orchestrator/case-content.html) · [返回项目首页](../../README.md)

场景是为「下班前十分钟」制作首月内容计划：面向入职 0—3 年的职场新人，一人每天最多 30 分钟，不露脸，四周 12 条，每条不超过 60 秒。账号和会议笔记是为展示编写的设定；**工作流与模型调用真实执行，视频和账号并未实际制作或发布**。

## 这次实际做了什么

使用 commit `1f36dba95ef70a0f3c3559cac16acd9898622ad9` 的原始 `workflows/一人公司-做内容.yaml`，未改模板。通过已有 Claude CLI 登录接入，以编程接口覆盖模板的默认供应商；开启验收，失败重试为 0，单次调用超时 180 秒。Claude Code 2.1.90，未指定模型，AO 没有返回精确模型名称。文本连接器关闭工具，因此没有检索平台资料、拍摄或发布视频。

| 记录 | 时间（UTC） | 耗时 | 结果 |
| --- | --- | --- | --- |
| 首轮 [run.json](run.json) | 2026-09-17 05:14:47—05:20:17 | 329.903 秒 | 5/5 步完成；选题和日历模型验收通过 |
| 带反馈续跑 [revision.json](revision.json) | 2026-09-17 05:20:47—05:22:52 | 125.443 秒 | 复用前三步；重做编导和运营；日历模型验收通过 |

首轮输出定位、两类观众画像假设、十个选题、第一条视频脚本和四周日历。人工发现脚本要求真人出镜、日历把 2026-09-21 标成星期日。原模板给编导的任务只引用选题库，没有直接引用完整原始需求；该步骤也未配置 `acceptance`。

通过 `resumeDir`、`fromStep: 'script'`、`feedback` 使用原库续跑能力，对应 CLI 的 `--resume`、`--from`、`--feedback`。前三步原文复用，编导收到旧稿和[反馈意见](feedback.txt)，运营使用新脚本。修订稿明确不出镜，包含完整提示词、虚构输入与三行待办表，排期的 12 个日期与 2026 年星期对应；原有十个选题之外补充两个进阶复用主题。

## 这说明了哪些能力

- **角色接力和变量传递**：老板定方向，研究员构建画像假设，策划列选题，编导写脚本，运营排日历。完整需求是否传到相关步骤，仍取决于模板引用。
- **产出与运行档案**：每步输出、耗时、状态、验收结果可回看；可明确追溯偏差出现的位置。
- **定向反馈与续跑**：修订局部步骤及其下游，避免重跑已完成的前三步。
- **模型验收及其边界**：两项首轮验收都通过，仍出现原始约束遗漏。检查表应包含实际业务约束；通过不代表已经可以发布。

这次是固定角色的串行工作流，没有展示自动选人、并行执行、媒体生成，也没有与单次提示词做质量对照。

## 保留在原文中的问题

页面没有替模型润色后再冒充原始输出，以下问题随原文展示并另加人工注释：

- 修订脚本仍出现未经验证的“屏幕录制类对标值”，运营对抖音推荐时段有无来源判断。目标阈值应当作假设。
- 0:04–0:05 安排一句较长口播，难以按标注时长读完；“不漏项、不乱猜”也是过强承诺，需要补人工核对。
- 第 10 次发布使用“做了 12 条视频”的回顾式标题，与实际阶段不符。
- 30 分钟是制作预算，未实测；运营没有逐日落实制作动作，回复评论还会额外占用时间。
- 结果表有三格“待确认”，脚本却写成两处；“9月25日前”被缩写为“9月25日”。固定日期与节假日顺延的规则也需统一。

提示词对应的待办表是编导同时生成的演示产物，没有独立运行该提示词进行二次测试。页面中所有观众画像、增长预期和运营阈值均未得到真实账号数据验证。

## 材料与复现

- [brief.txt](brief.txt)：首轮完整输入。
- [feedback.txt](feedback.txt)：人工反馈。
- [run.json](run.json)、[revision.json](revision.json)：AO 返回值，额外补充来源条件，移除顶层本地工作流绝对路径；输出正文未修改。
- [editorial.json](editorial.json)：中文讲解、人工观察和原文节选。构建器断言每段节选确实存在于对应记录。
- [运行脚本](../../experiments/run-content-case.mjs)：导入固定版本构建后的 AO，引擎本地档案保存到被忽略的 `.tmp/agency-orchestrator-content-launch/`。

在仓库根目录执行以下命令会重新调用模型并覆盖这两份案例记录；复现实验前先另存现有记录。前提是上游固定版本已安装依赖并构建，Claude CLI 已登录且可用。

```powershell
node projects/003-agency-orchestrator/experiments/run-content-case.mjs
node projects/003-agency-orchestrator/experiments/run-content-case.mjs --feedback
```

首轮 AO 记录 token 为输入 0、输出 12,945；续跑为输入 0、输出 5,474。这是接口返回的运行字段，不能视为完整用量或账单，也不用于推算费用。模型生成有随机性，复现不保证相同内容或耗时。

网页构建只读取已保存文件，不会重新调用模型：

```powershell
python projects/003-agency-orchestrator/web/build.py
```

已核对原文节选、前三步复用、12 个日期的星期、页面内部链接与本地 HTTP 可达性；未做浏览器视觉或交互验收。

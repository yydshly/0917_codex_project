# 能力、场景与验证边界

基准及源码链接见 [sources.md](sources.md)。本次未连接真实网关；区分源码存在实现、上游截图、本地教学示例与运行测量。

## 从突增定位设备与服务

情景：晚上网络变慢，希望找出主要流量来源。可按“网关和时间 → 趋势峰值 → 设备统计 → 域名和目标 IP”阅读。设备使用来源 IP，域名通常来自 `host` 或 `sniffHost`。这是分析路径，不代表产品自动诊断故障原因。

研究页“总览”和“域名”展示上游原图。若 API 只看到 NAT 后的来源地址，不能保证区分每个终端；CDN 地址也不能直接等同于单一服务或用户。

## 解释分流结果

情景：预期某服务直连，实际使用了代理。Clash 连接提供 `rule`、`rulePayload`、`chains`；Surge 优先从请求备注解析策略决策路径，失败时用策略名称回退。研究页“规则”展示统计与策略路径。

策略链是配置选择关系，不代表 traceroute 的网络逐跳路径；Neko Master 根据元数据呈现关系，不在这条统计链路中执行转发。

## 查看地理位置与归属

情景：大量连接的目标属于哪些国家与网络组织？GeoIP 支持在线和 MaxMind MMDB，缓存、请求合并、队列与失败冷却减少重复查询。研究页“地区”展示上游原图。

位置来自目的 IP，未知地址可能显示 Unknown；不能当成访问者实际位置。**Local 模式仍存在查询失败后的在线回退**，不是严格离线承诺。

## 历史与实时兼顾

情景：既要看当前变化，又要回看昨天。新增量一份进入内存，一份进入批量缓冲；查询将数据库历史和待落盘数据合并，减少写入而不让界面等待批次完成。

本地增量实验依次输入 10 → 13 → 13 MB，新增为 10 → 3 → 0 MB；模拟落盘将内存量转入数据库，显示总量不变。示例缩小为单连接、单方向、单维度，不代表实际采集延迟或并发行为。初见的累计值归入采集时刻，不能还原此前的精确时间分布。

## 跨网络汇总

情景：中心面板在 NAS / 服务器，不同网关位于不同局域网。直连要求中心可以访问网关 API；Agent 在网关旁采集，再主动上报中心，不要求中心反向直连远程网关。

该提交 Go Agent 对 Clash / Surge 都通过 HTTP 取快照；直连 Clash 才使用 WebSocket。Token、后端 ID、心跳及 requestId 去重支撑多网关接入。Agent 队列在内存中，超出上限会丢弃旧数据并记录 dropped；中心去重也有时效，不能推出断线零丢失或严格 exactly-once。

## 部署和界面便利性

上游有 Docker / 源码运行方式，中英文、主题、PWA。PWA 不代表断网仍能获取实时流量。SQLite 默认可用；ClickHouse 面向更多统计数据，但收益需要实际规模与查询基准测试。

本研究网站仅为静态展示，不能把完整采集后端部署到 GitHub Pages。真实 Neko Master 需要持续运行后端与数据库，以及到网关或 Agent 的网络连通性。

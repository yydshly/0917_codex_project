READ THE CLIENT / FOLLOW THE DATA

为什么读客户端，就能知道流量？

Clash 负责转发并计数。
Neko Master 负责采集、保存和展示。

有网络请求时，Clash 在应用与远端之间转发数据，所以能在本地累计上传、下载字节，并记录目标和所选节点。选择 DIRECT 时，则由 Clash 直接连接网站。并不是每次启动都向远端同步流量账单。

业务数据

应用 → Clash → 节点 → 网站

网页、文件等数据沿此路径传输，响应反向返回。这里以选择代理节点为例；无业务请求时不意味着始终有业务流量。

统计数据

内核计数 → 管理 API → Neko

Neko Master 读取所配置的 Clash 内核，可以位于电脑或路由器上；无需登录远端节点，也无需解密网页来统计字节。

系统代理与 TUN，区别在哪一步？

系统代理由应用主动使用代理地址，HTTPS 可通过 HTTP CONNECT 把域名交给 Clash；TUN 由操作系统按路由把 IP 包交给虚拟网卡，再由内核结合协议栈处理。两种方式都使用操作系统与 IP 层，并可共用后面的出口和统计。

全局模式、DNS 和 IP 检测分别说明什么？

GLOBAL 只决定进入内核后的出口，不会强迫所有应用使用系统代理。DNS 要分清谁解析、问谁、从哪里查询；TUN 不保证 DNS 经远端。IP 检测只证明那次请求的出口，不能证明全部流量路径，也不保证其他网站采用相同地区或信誉判断。

为什么切换 TUN 后可用性可能变化？

先检查相关连接是否进入 Clash、是否走 DIRECT 或不同节点，再比较 DNS、IPv6、旧连接、缓存以及账号和服务限制。切换结果不能单独证明原因；TUN 不会自动提高 IP 信誉。

统计数字是否等于套餐用量？

不一定。Clash 记录经过该内核的连接字节，Neko Master 计算增量并保存历史。物理网卡封装、重传、其他设备、采集间隙及服务商计费口径都会影响可比性。

05 / READ WITH CONTEXT

看得见什么，也取决于数据从哪来。

可见范围

只分析网关提供的记录

未经过网关、缺失的域名字段、断采期间已经结束的连接，都无法保证补齐。没有 HTTPS 内容解密能力。

地理补全

Local 不等于严格离线

该版本本地 MMDB 不可用或查询失败时可能回退在线查询；位置来自目标 IP，不是访问者的实际位置。

可靠性

重试有用，但有状态窗口

Agent 使用内存队列，溢出会丢弃旧数据；中心 requestId 去重也在内存中。重启和晚到重试仍需要真实测试。

存储选择

ClickHouse 有多种写入模式

默认、减少 SQLite 写入、CH_ONLY_MODE 的条件不同。不能把它描述为始终双写，也不能等同于完全替代 SQLite。

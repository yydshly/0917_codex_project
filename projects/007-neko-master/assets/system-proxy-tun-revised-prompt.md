1“两个入口，一个内核”：左蓝色流程“浏览器遵循代理设置 → 本机回环 TCP/IP → Clash HTTP / mixed 入口”，箭头标注“127.0.0.1:7890（示例）”“CONNECT 网站域名:443”。说明“浏览器不必先获得网站 IP；通道建立后传输网站 TLS 握手与密文。”右绿色流程“应用 → 操作系统路由 → TUN 虚拟网卡 → Clash TUN 协议栈”，说明“匹配的 IP 包进入 TUN；协议栈处理 TCP 状态与重组、适配 UDP。应用无需配置代理，接管范围由路由决定。”两路必须汇入同一个独立大框“Clash / Mihomo 内核：目标信息与 DNS 映射 · 规则 / GLOBAL 选择出口 · 读写计数与双向转发”。强调“全局模式仅决定已进入内核的流量走哪里。TUN 本身不负责选节点或远端加密。”
2“远端代理如何转发”：例子为“HTTPS 网站 + 普通 Trojan 节点”。流程“本机 Clash 出站 → 远端 Trojan 节点 → 网站”。箭头分别标注“连接① TCP + 外层 TLS”“连接② 节点另建 TCP”。节点说明“解除外层 TLS、读取目标，连接网站并转发内层 HTTPS”。下方“内层 HTTPS：浏览器 ↔ 网站。解除外层加密不等于解密网页。”独立小支路“DIRECT：本机 Clash → 网站”。说明“网站看到实际公网出口 IP；同一出站可得到同一 IP。响应沿链路反向返回。”
3“DNS 是三个问题”：三小卡“谁发起解析？”“问哪个 DNS？”“查询从哪里出去？”说明“HTTP 系统代理可把域名直接交给 Clash，后续解析位置取决于配置与出站协议。TUN 可通过 dns-hijack 接管匹配 DNS；上游和出口仍由配置决定。普通 DNS 劫持不等于解密 DoH / DoT。Fake-IP 可先返回占位地址，再由内核映射回域名。”
4“Neko Master 读取哪里？”：紫色流程“Clash 内核累计连接字节 → 管理 API /connections → Neko Master 计算差分、保存历史”。强调“读取所配置的 Clash 内核，可以在电脑或路由器上。不需要与远端节点同步统计。”说明“管理接口端口依配置；不等于代理端口。统计范围不等于物理网卡全部字节或服务商计费用量。”
5“真正的差异”：三列表格“比较项 | 系统代理（常见 HTTP） | TUN”。四行“接管条件 | 应用遵循代理设置 | IP 包匹配路由”“协议支持 | TCP 网页连接，不承载通用 UDP | 可适配 TCP / UDP，受出站限制”“DNS | 可由代理侧解析域名 | 可接管匹配 DNS，依配置处理”“出口 IP | 同一出站可得到同一 IP | 同一出站可得到同一 IP”。
6“切换后可用性不同，怎样排查？”：写“仅凭系统代理不行、TUN 可以，不能确定原因。”列出“核对相关连接是否进入 Clash”“核对 DIRECT / 节点选择”“比较 DNS、IPv6、旧连接与缓存”“检查出口、账号和服务限制”。醒目结论“IP 查询网站只证明那次请求的出口，不能证明全部流量的路径。TUN 不会自动提高 IP 信誉，也不保证解除地区限制。”

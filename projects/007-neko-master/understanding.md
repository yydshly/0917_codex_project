# Neko Master、Clash 与远端节点：我们的理解

## 一句话说明能力

Neko Master 从 Clash / Mihomo 等代理内核的管理 API 采集连接和流量信息，计算增量、保存历史，再按设备、域名、IP、规则和代理节点展示。Clash 可以运行在电脑或路由器上，Neko Master 不必与它同机。

## 为什么读取客户端就能统计？

访问网站时，Clash 转发应用的数据；选择代理节点时与远端节点交互，选择 DIRECT 时直接连接网站。数据经过它的读写路径，所以内核可以本地累加上传、下载字节，并记录目标、规则和出口。不是每次启动就与远端同步流量账单，也不是没有请求时仍不断产生业务流量。

- 业务路径：应用 → 本机 Clash → 远端节点 → 网站；响应反向返回。
- 统计路径：Clash 内核计数 → 管理 API `/connections` → Neko Master → 数据库与面板。

Neko Master 不需要登录远端节点，也不需要解密 HTTPS 正文来统计字节。已结束连接、采集间隙或内核重启可能影响历史完整性；持续采集与持久存储使记录可回看。

## 系统代理与 TUN：入口如何不同？

系统代理要求应用遵循代理设置。浏览器连接本机代理监听端口；访问 HTTPS 时可发送 `CONNECT 网站域名:443`，不必先获得网站 IP。该本机连接仍经过操作系统 TCP/IP 回环。

TUN 是虚拟网络接口。操作系统按路由交付匹配的 IP 包，再由 Clash 结合协议栈处理 TCP 状态与重组、适配 UDP。应用无需配置代理。TUN 本身不负责远端认证、加密或选节点，也无需与远端使用相同 IP。

两种入口汇入内核后，可共用规则、出站节点和计数。GLOBAL 只决定进入内核后的出口，不会强迫所有应用使用系统代理；TUN 也受排除路由等配置限制。

## 远端如何交互？

以普通 Trojan 转发 HTTPS 为例：本机 Clash 新建到节点的 TCP / TLS 连接，将认证、目标和待转发字节送给节点。节点解除外层 TLS，再新建到网站的 TCP 连接，转发浏览器与网站之间的内层 HTTPS 数据。解除外层加密不等于解开网页正文；通常也不是原始 IP 包整包透传。

网站看到实际出站的公网 IP。系统代理与 TUN 若使用相同实际出口，可以呈现相同 IP。DIRECT 由本机直接连接网站，通常呈现本地网络的公网出口 IP。真实路径可能包含 NAT。

## DNS、出口 IP 与地区限制

DNS 需要分清谁发起解析、询问哪个服务器、查询经过哪个出口。HTTP 代理可接收域名；TUN 可以结合 DNS 劫持及 Fake-IP 映射，但不保证 DNS 经远端节点。DoH / DoT 是加密查询方式，不是出口选择；普通 DNS 劫持不等于解密它们。

IP 查询网站只能证明那次请求的出口，不能证明所有流量都走同一路径，也不能保证其他网站采用相同的 IP 地理数据库或信誉评分。TUN 不会自动提高 IP 信誉。

遇到系统代理失败、TUN 成功时，核对相关连接是否进入 Clash、是否选择 DIRECT 或不同节点，再比较 DNS、IPv6、缓存、旧连接以及账号或服务限制；仅凭切换结果不能确定原因。

## 统计的边界

内核计数只覆盖经过该内核的相关连接。Neko Master 的展示不等于物理网卡全部字节，也不必与服务商套餐用量一致；网络封装、重传、其他设备和计费口径可能不同。

本文以 Clash / Mihomo 说明主流程；上游也支持 Surge 与远程 Agent。直连 Clash 使用 WebSocket 获取连接记录；固定版本 Go Agent 实际以 HTTP 轮询，二者不要混用。

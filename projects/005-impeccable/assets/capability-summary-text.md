2  用户明确方向，大模型细化项目的特殊要求

目标用户 / 任务 / 风格参考 → 模型提出布局、字体、颜色与交互方案 → 用户确认或修订

优秀方向：操作重效率 / 阅读重理解 / 营销重行动 / 展示重体验；风格明确不等于任务已经好用。

PRODUCT.md 保存产品事实；DESIGN.md 保存确认的视觉规范；页面说明保存局部目标。明确需求优先于默认偏好。

3  宿主 AI 读取对应指南，推理并修改真实代码

读取项目 → 诊断问题 → 明确修改策略 → 编辑 HTML / CSS / 组件 → 运行页面

例如：区分标题与正文、按任务重组布局、保留搜索能力、补充长文本和空结果状态。

约束形式：Markdown 指令进入模型上下文。它依赖模型理解与执行，并非强制求出“最优设计”的算法。

对我的意义：给研究网页一套可复用的改进方法与验收参考

让读者理解项目能力、原理与证据；让看板用户顺利检索、筛选与恢复操作。

每轮针对明确问题持续优化，并沉淀已确认的规范；不追求无目标的反复改版，也不只追求规则零命中。

阶段认识与后续研究

模型越强，通用常识提醒的额外价值可能降低；项目上下文与实际验证仍有意义，规则也需更新。

已做源码分析与有限看板实验；具体命令、风格定制、Live 和相对模型的实际增益，仍需逐项梳理与验证。

核心：通用约束来自 Skill；特殊要求由用户与模型共同明确；具体实现靠大模型，最终效果靠验收。

先理解它能做什么

以下为上游能力的初步目录。24 个命令与 61 条规则不代表已全部验证，具体能力和效果仍需后续逐项梳理。

建立产品与设计上下文

init 明确产品事实，shape 规划界面，document / extract 沉淀规范与组件。避免每次生成都从零猜测。

评审和改善已有页面

audit 检查实现，critique 评审体验；typeset、layout、polish 调整层级、间距和细节。

覆盖真实使用状态

harden 处理长文本与异常，adapt 适配屏幕，clarify 改善文案，onboard 完善首次体验。

探索并选择设计方案

bolder / quieter 调节表现，live / generate 支持页面元素的多方案预览。需要宿主 AI 与本地项目。

查看完整 24 个命令与使用边界

规划与沉淀：craft、init、document、extract、shape；评估：critique、audit；改进：polish、bolder、quieter、distill、harden、onboard；增强：animate、colorize、typeset、layout、delight、overdrive；修正：clarify、adapt、optimize；迭代：live、generate。

当前源码已将 craft 标为普通新建任务的废弃别名。pin、hooks、doctor 等管理入口另计。能力清单表示上游提供了工作流程，本次仅实践排版、布局、健壮性指南与检测。

技术原理：从指导到反馈

  1. 加载上下文PRODUCT.md 产品事实
    DESIGN.md 视觉规范
  2. AI 执行设计指南按任务读取参考文件
    编辑真实前端代码
  3. Rust 引擎扫描源码 / 静态 HTML / 浏览器
    输出可定位的规则发现
  4. 查看效果并修正检查布局与交互
    确认最终实现

核心规则也可编译成 WebAssembly，在浏览器扩展与页面工具中复用；部分宿主可通过 Hook 在编辑后自动检查。Live 使用本地服务连接浏览器与 Agent。本页是静态实验展示，没有安装 Hook，也没有运行 Live 服务。

实际运行的检测

官方 engine-v0.1.5（自报版本 4.0.0）；静态文件、桌面与手机 URL 各扫描两版。统一使用 --no-config，未屏蔽规则。

对我的意义：有目标地改善研究网页

把它作为可复用的方法和验收参考；具体适用性与增益仍需实际任务验证。

通用方法可以复用

排版、布局、反馈、空状态等常见要求不必每次从零组织。作者审美是默认偏好，不是永远正确的标准。

特殊要求需要定制

我明确用户、任务、风格参考和限制；大模型据此提出布局、字体、颜色和交互方案。缺少明确风格时，模型可以提案，由我选择或修订。

持续优化要有停止条件

每轮选择一个实际问题，修改后检查并验收，再决定下一轮。将确认的产品事实与设计规范保留下来，避免无目标地反复改版。

随着模型升级重新评价

更强模型可能默认掌握通用设计常识，Skill 的额外收益可能下降。项目事实与运行证据仍有价值，但工具和规则也需更新、精简。

“优秀”首先取决于页面的任务

阅读 Read：让人理解内容；操作 Operate：让人完成任务；说服 Persuade：让人理解价值并行动；体验 Experience：让人感受和探索作品。

我的研究说明页优先回答“库做什么、如何工作、有什么证据”；研究看板优先让用户找到项目并完成筛选。风格只能提供外观方向，任务成功还需要实际验收。

当前认识证据范围后续要做什么
核心是前端优化指南与辅助工具固定源码分析；定向应用指南；有限看板实验逐项梳理命令输入、输出、适用条件和实际效果
风格和特殊要求仍依赖模型判断指南中的项目上下文与设计规范机制用真实页面验证不同风格和任务约束能否稳定落实
可以按具体目标多轮使用工作流与上下文机制分析验证多轮优化是否持续有益，何时应停止或回退
额外增益可能随模型能力变化研究判断，尚未量化同任务、同模型、同预算比较有无 Skill；另验 Live / Hook

阶段结论：目前形成的是对库定位和原理的理解，不能把教学看板的 43 → 0 当作 Skill 必然带来收益的证明。具体能力、适用场景和实际增益仍需后期梳理与验证。

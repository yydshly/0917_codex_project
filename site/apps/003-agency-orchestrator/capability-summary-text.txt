01

它是什么：角色、流程、模型，各自负责什么

角色与方法：定义“怎么想”

001 / 002 提供角色身份、专业方法与交付要求。
角色正文 + 可选 Skills 成为提示材料；团队保存常用阵容。

AO 引擎：安排“怎么接着做”

将输入、角色、任务、依赖与检查写成 YAML。
解析配置、传递上下文、调用连接器、调度步骤并保存档案。

模型与外部工具：实际执行

API / 已登录 CLI / Ollama 生成内容。
媒体服务生成图像、视频和声音；ffmpeg 合成；人负责核查和业务交付。

固定快照规模：69 个工作流（含 13 个英文模板）｜276 个中文角色 / 191 个英文角色｜Apache-2.0；依赖各循其许可

02

能力地图：从组队，到执行，再到带走成果

本区为源码确认；实际覆盖见第 08 区

A  建立流程与复用阵容

自然语言 compose 选角色、拆任务、生成 YAML；也可直接用内置模板。
私有角色、Team、步骤 Skills、Prompt Lab；角色安装支持 8 个目标。

B  依赖、分支与有界循环

depends_on 构建执行图；同层任务可按并发设置运行。
文本条件 contains / equals；部分分支合流；有限回跳，循环最多 10 次。

C  人工输入、检查与恢复

human_input 收集信息；approval 记录回答。
assert 检查结构，acceptance 让模型核验内容；超时、部分错误重试、档案续跑与反馈返工。

D  模型与媒体接入

支持 API、CLI 登录、本地 Ollama；可按步骤配置模型。
image / video / tts / concat 连接生成、配音和合成流程；需要对应服务与运行环境。

E  产物、导出与文件落盘

逐步输出、Markdown / JSON 档案、单文件 HTML 报告。
导出 docx / pdf / xlsx / pptx / skill / plan；从代码块写出项目文件。

F  使用入口与外围集成

Web Studio、Electron 桌面、CLI 和 Node 编程 API。
MCP 提供 6 个工作流工具；社区模板、Webhook 通知；周期触发依赖外部调度。

03

内部怎样工作：输入 → 调度 → 生成 → 检查 → 归档

输入层

完整需求 + 证据材料 + 生产约束 + 模型配置 → 已有 YAML；或者先通过 compose 生成 YAML，再人工审阅。

1  解析 / 校验

检查字段、角色、变量与依赖；validate / plan 可预查。

2  依赖调度

建图后按层、按批执行；判断条件与人工节点，必要时有限循环。

3  组装上下文

角色 + Skills + 当前任务 + 显式引用的输入 / 上游产出。

4  调用连接器

按配置请求文本模型或媒体服务；记录耗时、状态与可用用量。

5  检查 / 保存

文本先 assert，再 acceptance；记录输出与核验结果，交给下游。

反馈闭环：查看每步产出 → 找到问题步骤 → 旧稿 + 意见定向重做 → 下游使用新结果；此前已完成步骤可复用。

上下文如何传递

output 命名产出，{{变量}} 把它填进后续 task；depends_on 控制执行顺序。
关键约束需显式传给相关步骤。角色不会自动共享全部需求或拥有长期记忆。

检查不是同一种保证

assert：结构不符返工一轮，再不符则步骤失败。
acceptance：内容不符最多返工一轮；仍不通过或验收不可用，可以警告后继续。两者要分别读。

04

如何使用：先跑通一条小流程，再加角色和分支

① 准备运行条件

Node.js ≥20；固定版本源码安装依赖并构建。
选择 API 凭据、已有 CLI 登录或 Ollama；确认角色与模板可加载。

② 把任务说完整

写清目标、受众、原始材料、禁止事项和交付格式。
把预算、截止日期、不可猜测字段、通过标准传到相关步骤。

③ 预查后再执行

新手：Studio 选模板、填输入、看分工、运行。
可复用任务：CLI / API 跑 YAML；先 validate / plan，核对依赖和输入。

④ 检查并定点修改

分别查看执行状态、验收结果和最终内容。
从问题步骤带反馈续跑，再人工核对、测试或发布；保留具体档案。

最小命令示例｜在已构建的上游目录执行；brief.txt 放完整需求，Claude CLI 已登录

node dist/cli.js validate workflows/一人公司-做内容.yaml

node dist/cli.js plan workflows/一人公司-做内容.yaml

node dist/cli.js run workflows/一人公司-做内容.yaml -i direction=@brief.txt --provider claude-code

node dist/cli.js run workflows/一人公司-做内容.yaml --resume last --from script --feedback "只录屏，不露脸" --provider claude-code

实际案例使用对应的 Node API；多流程共用输出目录时，把 last 换成明确的运行档案路径。

首轮：329.9 秒，完成 5 / 5 步

模型验收：选题和日历均通过。人工却发现脚本要求真人出镜，日期把 2026-09-21 标成星期日。
编导任务只引用选题库，未直接带完整原始需求，也未配置 acceptance。

返工：125.4 秒，复用 3 步 / 重做 2 步

给编导旧稿和明确反馈，下游运营使用新脚本。出镜方式与 12 个日期已修正。
仍有口播过长、无来源平台判断、“做完12条”的过早复盘与工作量遗漏，需人工再处理。

这验证了：角色接力、产物留档和局部返工。没有验证：真实账号增长、30 分钟产能、视频生成，或优于单次提示词。

06

限制与边界：避免把编排能力误认成结果保证

工具与事实边界

角色提示词中的 tools 不会自动授予搜索、数据库或业务系统权限；给 URL 不等于已读取网页。
通用文本路径没有自动检索循环。应先准备可靠材料，外部事实需独立核对。

审批与验收边界

approval 只读取回答：输入 no 也可能继续，须给下游加明确条件。
acceptance 返工后不再重跑 assert：可能内容过了、结构却坏了，需最终独立检查。

并发与资源边界

顶层 provider 为 CLI 时并发降为 1；API 并发受配置、限流和依赖影响。
重试不是无限恢复；--budget 是模型分配策略，不是费用硬上限。用量字段可能不完整。

执行与媒体边界

Claude Code 文本连接器关闭工具；Codex CLI 使用只读沙箱。文件落盘不代表已运行测试或部署。
媒体需服务；合成需 ffmpeg，concat 无验收/断言；视频验收失败默认不重生成。

运行环境与数据边界

Studio 是本地单用户服务，不能直接当多租户企业平台；密钥保存在本地不等于推理在本地。
CLI 复用登录仍有账号与额度条件；本地模型需要算力。GitHub Pages 仅承载静态结果。

格式与质量边界

PDF 依赖外部排版工具，缺失时回退 HTML；Excel 主要提取 Markdown 表格。
多角色可能放大遗漏、增加时间与成本。作者有限评测有输有赢，不能推断普遍质量提升。

07

有什么意义：把一次生成，变成可检查的工作过程

适合使用的地方

固定输入、多个分工、明确交付、需要追溯和经常返工的重复任务。
例如内容策划、PRD 拆解、多角度评审、已有证据材料的研究汇总、媒体生产流程。

不宜直接托付的地方

一次简单问答；缺少真实证据的研究；要求自动联网、执行代码或操作业务系统的任务。
严格审批、强权限治理、高风险结论和确定性结果，需要额外机制与人工责任。

对我们最有价值的用法

来源材料 → 能力提取 → 架构 / 限制评审 → 中文交付 → 人工核对。
先固定证据包和小流程；与强单次提示词比较事实错误、来源、用时、用量和修订量，再扩展。

我们的证据到哪里：确认、实测与未验证分开看

源码确认 + 选定核心测试

构建完成；10 组纯函数 / Mock 测试，158 项通过。
额外实验确认 approval 的 no 不自动阻断、验收后断言缺口，以及 API / CLI 并发表现。非全量测试。

一次真实场景 + 一次定向返工

原始“做内容”模板未修改；Claude Code 2.1.90，未指定模型，记录未返回精确模型名。
共两轮生成记录，保留逐步原文和反馈；人物画像与运营目标属于未验证假设。

仍待实测的部分

自动组队质量、其他供应商兼容、Studio / 桌面完整交互、媒体生成、导出排版与外部集成。
尚未做同条件质量对照、真人制作计时、真实运营实验、长期可靠性或完整安全审计。

核心判断

AO 的已证实价值在流程组织、材料传递、产物追溯和定点返工。要获得可靠交付，仍需把约束写进步骤、把证据提供给模型，并独立检查最终结果。

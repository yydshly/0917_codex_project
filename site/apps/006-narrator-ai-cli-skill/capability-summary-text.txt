# 总览图文字说明：从素材到解说视频

我们讨论后的核心理解：**这个库提供从素材到成品的操作方法与规则，云端服务提供实际制作能力。** 平台或用户提供素材，助手结合用户要求按 Skill 安排步骤，经客户端调用服务端，最后取得视频。

本图依据公开资料整理，属于原创研究说明图，不是运行截图。生成入口为本子项目 `render_summary.py`，输出同内容的 PNG 和可编辑 SVG；使用 Pillow 绘制，未使用生成式图片模型。

## 01 · 谁负责什么

| 角色 | 职责 |
| --- | --- |
| 用户 | 提出影片、语言、风格、声音、版式等要求，提供素材或选择平台资源 |
| Skill | 说明有哪些能力、怎么调用、需要什么输入、按什么顺序操作和如何处理错误 |
| AI 助手 | 理解要求，参考 Skill 组织任务、选择参数，读取结果并决定下一步 |
| CLI 客户端 | 发送结构化请求，上传文件，提交与查询任务，返回状态与产物 |
| 服务端 | 执行文案、配音、剪辑数据与视频合成任务，使用模型和媒体处理程序 |

Skill 指导助手，助手调用客户端，客户端访问服务端。服务端并不是 Skill 本身；客户端也不是独立理解用户需求的模型。

## 02 · 素材怎么进入

平台素材路径：客户端查询平台目录 → 取得视频与字幕的 `file_id` → 直接引用。

本地上传路径：准备视频与 SRT → 客户端申请预签名上传地址 → 将文件上传到对象存储 → 回调确认 → 取得可引用的 `file_id`。

确认素材后，选择解说风格、音色和 BGM。影片搜索只取得影片资料，不等于下载电影；素材也不是全部由 Skill 仓库自带。后续任务按文件 ID 引用素材，无需每步重新上传。

## 03 · 每个制作步骤怎样交互

1. 助手按 Skill 组织当前步骤的参数。
2. CLI 通过 API 提交 JSON 参数和鉴权信息。
3. 服务端创建异步任务，返回 `task_id`。
4. 客户端按任务 ID 查询；服务端返回进度、错误或完成结果。
5. 助手读取状态和产物，将正确的引用传到下一步骤。

整体制作链：生成解说文案 → 生成剪辑数据 → 合成视频 → 可选视觉包装。

原创路线为原创文案、快速剪辑与合成；二创路线使用参考风格或预设风格生成文案，再剪辑与合成。`file_id` 引用文件，`task_id` 查询进度，`task_order_num` 关联任务；两条路线合成时的关联编号来源不同，必须遵循具体接口约定。

用户需求由外层助手理解和组织；服务端模型参与具体内容处理。后端的逐句画面匹配、模型路由与渲染算法未完整公开，不能据此推定每一步都由模型自行决策。

## 04 · 约束如何处理

- **Skill 的指导规则**：素材 ID 必须真实；文案、音色、标题语言一致；按前置依赖执行并确认资源；失败后按规则处理。由助手阅读并遵守，并非绝对强制。
- **程序已经实现的检查**：CLI 检查任务类型和 JSON 等；服务端文档与错误码表明有鉴权、参数、额度等检查。不满足时返回错误，但不能据此认定所有 Skill 规则都被代码校验。
- **实际效果条件**：素材与字幕质量、模型输出、配音剪辑质量以及助手是否正确执行流程，共同影响结果。流程规范不能保证成片必然优质。

## 05 · 最终效果与研究边界

将解说稿、原片画面、配音、字幕和 BGM 组合为成品视频，返回 MP4 链接；可选视觉模板、横竖屏布局与分集。独立任务还包括声音克隆和文字转语音。

本次未调用云端生成，成片效果、耗时、费用与运行可靠性待实测。图中的编号代表阅读顺序，不代表服务端只有五个接口。

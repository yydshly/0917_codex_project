# 011 · Security Audit Skill

从业务逻辑、身份权限、输入接口、数据流及底层环境等角度，指导 AI 检查代码和业务实现的安全质量。Skill 通过目标范围、路径追踪、覆盖记录、证据门槛、独立复核、执行边界和输出规范约束 AI，将疑点整理为可追溯的安全结论与修复建议。

**这里的质量把控指安全维度。** 它检查“不该发生的操作是否可能发生”，不等同于完整功能、可读性、性能和可维护性评估，也不替项目实现权限系统。完整讨论见 [我们的理解、约束机制与历史项目对比](understanding.md)。

**本项目是源码研究与静态教学展示。未安装该 Skill、未启动真实审计、未运行上游代码；网页案例为人工编写的假设场景，不代表检出的真实漏洞。**

## 从入口到安全质量

**谁进入 → 能输入或操作什么 → 认证授权与数据转换 → 最终触达的资源 → 边界是否失效 → 实际证据。**

检查包含业务状态、权限与租户隔离、输入和接口、数据与秘密、组件协议以及内存和部署环境，也覆盖错误处理、批量、重试、并发、撤销和恢复路径。它进行系统性检查并披露遗漏，不能保证系统完全安全。

Skill 通过七类要求约束 AI：目标、路径、覆盖、证据、独立性、执行、输出。落实方式分三层：**指令由模型遵守，记录由程序校验，执行隔离由操作系统强制实现**。详见 [逐项约束表](understanding.md#skill-的七类约束)。

## 与之前的 Defending Code 有什么不同

我们在 2026-09-15 研究过 [Defending Code](https://yydshly.github.io/0915_codex_project/008-defending-code-harness/)。两者都用模型提出漏洞假设，再用证据和独立复核约束结论。

- **本库：**提供跨领域审计流程与记录校验，重点是覆盖追踪、证据门槛和最终报告；运行能力由宿主提供，输出修复建议。
- **Defending Code：**提供更多可执行框架代码，默认面向 C/C++ 内存漏洞，使用 Claude Code、容器与 ASAN；另有候选补丁生成和验证命令。
- **共同边界：**均不能代表通用代码质量检查或安全保证；本研究未做两者检出效果对照。

## 能力覆盖范围

基础调查包含 9 组方法：注入、访问控制、资源与文件处理、密码学与秘密、业务逻辑、功能滥用与数据泄漏、组合漏洞与信任边界、开放探索、基础暴露检查。

10 个专项领域包括：内存安全与二进制；AI / LLM / MCP；HTTP 与认证协议；浏览器端；供应链与发布；云与部署；RPC 与消息；资源耗尽与可用性；数据隔离与生命周期；桌面、移动端与本地 IPC。

这些文件是给模型的调查和验证指令。是否选用取决于项目中的真实信任边界，不能仅凭编程语言或依赖名称决定；也不能把覆盖领域列表当作准确率或检出保证。

## 如何工作

1. 侦察：分工梳理架构、权限、输入路径和本地执行条件。
2. 调查：根据覆盖单元分配代理，沿输入到敏感操作的路径检查；覆盖检查代理指出遗漏。
3. 验证：每个去重候选交给未参与发现的代理，尝试推翻结论。
4. 记录：主代理写入 JSON，运行结构与语义一致性校验。
5. 复核：检查最终记录中的源码、条件、影响和修复建议；重大修改需要额外独立复核。
6. 报告：由最终记录生成汇总、详细发现和待验证说明。

标准和深度模式分开执行候选验证与最终记录复核；快速模式合并这两轮，但仍保留独立于发现者的验证。详见 [实现原理](architecture.md)。

## 三种结论

| 结论 | 需要什么 | 严重性 |
| --- | --- | --- |
| `confirmed` | 完整源码路径、具体边界失败、受限本地观察结果和成立条件 | 才可赋予等级 |
| `needs_validation` | 源码支持疑点，但存在明确、关键的未决事实，并给出验证计划 | 不赋予等级 |
| `rejected` | 源码、实际行为、有效控制或不成立的前提推翻候选 | 不作为漏洞展示 |

未经过候选验证的线索不能直接塞进 `findings.json` 当作待验证结论；预算不足时应保留在覆盖记录中并标记整轮未完成。

## 输入与输出

输入是目标仓库、范围、模式、可选代理调用预算、可用工具与以往审计材料。默认 `standard`，支持 `quick`、`deep` 和按路径或差异限定范围。

输出包括 `run-metadata.json`、`architecture.md`、`coverage-ledger.json`、`findings.json`、`REPORT.md`、`FINDINGS-DETAIL.md`、`NEEDS-VALIDATION.md`。主代理是共享文件的唯一写入者，子代理使用各自隔离的工作区。

## 实际边界与研究价值

- 仓库提供流程、提示指令、数据契约与校验程序。模型、子代理调度和操作系统沙箱来自宿主环境。
- 校验器验证字段与记录规则，不会证明源码引用描述正确，也不会自动证明漏洞成立。
- 目标代码执行要求断开外网、环境变量白名单、只读源码、隔离写入和明确资源限制；缺少必要能力时保留具体待验证阻碍。
- 流程检查源码与受限本地行为，不探测线上服务；提供修复建议，不直接修改目标源码。
- 单轮、快速、限范围或预算不足的审计不能当成“项目安全证明”。独立代理也可能出现共同遗漏。
- 对本研究仓库的价值：可复用证据标准、覆盖记录和反驳验证机制。真实检出率、误报率、成本与模型差异尚未验证。

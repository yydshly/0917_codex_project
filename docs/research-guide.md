# 研究与维护约定

## 编号与目录

项目目录统一为 `projects/NNN-slug/`，如 `projects/001-example-repo/`。编号由脚本按当前最大编号加一分配，最小宽度为三位，不按名称或研究状态重排。归档项目保留目录，不删除后复用编号。并行分支添加项目时，合并前解决编号冲突并重新同步索引。

## 新建与更新

在仓库根目录执行：

```sh
python scripts/projects.py new example-repo --name "项目名称" --repo https://github.com/owner/example-repo --summary "研究重点"
python scripts/projects.py sync
python scripts/projects.py check
```

第一条命令会创建目录和 `project.json`，并自动同步首页。后两条用于日常更新与一致性检查。

元数据字段：

| 字段 | 含义 |
| --- | --- |
| `id` | 固定整数编号，与目录前缀一致 |
| `slug` | 小写英文、数字和中划线组成的短名称 |
| `name` / `summary` | 项目显示名称与一句话研究摘要 |
| `repo` | 上游 GitHub 仓库的 HTTPS 地址 |
| `status` | `待研究`、`研究中`、`已完成` 或 `已归档` |
| `demo` | 实际可访问的 HTTP(S) 演示地址，尚未部署时留空 |
| `cover` | 相对于子项目目录的图片路径，例如 `assets/cover.png`；没有图片时留空 |
| `cover_alt` | 封面替代文本；设置封面时必须填写 |

首页索引和图片预览由这些元数据生成；其他 README 内容可以手工编辑。模板不参与索引，也不占用编号。

## 建议研究流程

1. 记录上游仓库、许可证和研究基准 commit。
2. 明确研究问题，将状态改为 `研究中`。
3. 在 `notes.md` 中记录环境、运行过程、源码入口和实验结果。
4. 把适合对外阅读的结论整理到子项目 README，并配上真实截图。
5. 需要演示时添加 `web/`，验证部署后填写 `demo`。
6. 更新状态和摘要，运行同步与检查，再提交变更。

## 上游源码

默认在仓库根目录的 `upstream/` 中克隆上游，避免将整个第三方仓库混入研究文档。此目录已被忽略。需要长期维护修改时再选择 fork 或 submodule，并说明来源和固定版本。

本仓库暂未指定统一开源许可证；第三方代码与素材沿用原许可证，后续添加本仓库许可证时不得覆盖其原有权利。

# 自行车与升降椅：我们的 3D 实现理解

这两个项目是**可运行、可检视、可复用思路的 3D 实现参考**。它们展示如何把网页界面、三维外观和产品行为组合成完整交互，不是自带全部业务功能的通用成品库，也不代表经过验证的工程仿真。

| 参考 | 核心价值 | 可迁移场景 |
| --- | --- | --- |
| [010 自行车](../projects/010-veloce-bike-studio/README.md) | 硬质零件、材质配置、传动与制动、配件装配、热点与特写 | 机械产品配置、结构教学、运动器材与设备展示 |
| [012 升降椅](../projects/012-lift-chair-studio/README.md) | 软包质感、条件调节、锁定、装配分解、乘坐滑行 | 家具配置、操作讲解、产品交互原型 |

## 技术分工

- React：界面控件、状态、选择与读数。
- Three.js：几何、材质、灯光、阴影、相机、拾取和渲染循环。
- 自定义 JavaScript：部件层级、建模、运动约束、暂停、边界及模式互斥。
- Vite：构建静态页面，使用相对资源路径部署到 GitHub Pages。没有应用后端。

数据流是“用户操作 → 配置状态 → 运动计算 → 三维节点 → 界面读数”。旋转、位移和材质切换是通用基础能力；固定销距链条、后仰锁定、分步装配和载人滑行等具体行为需要自行实现。

## 为什么自行车更容易做出质感

车架和轮组接近管、环等规则形状，程序化建模很适合；金属、车漆、橡胶的反射差异可突出结构。椅子软包更依赖连续曲面、织纹与缝线。人体还需要准确比例、关节过渡、衣物、接触姿态与自然动作。当前人物是简化几何拼接和固定坐姿，模型质量没有达到椅子与自行车的精细程度。

增加灯光、细分和分辨率不能替代人体建模。人物若需要真实感，应先换用或制作比例准确、带骨骼的模型，处理臀部、手和脚的接触关系，再加入动作及材质。React + Three.js 可以继续使用，不必因为质量升级重写整套应用。

## 下次提示词要说清什么

1. 对象与部件：有哪些零件，哪些固定，哪些随父部件移动。
2. 操作与规则：输入条件、调节范围、锁定、暂停、恢复及模式互斥。
3. 视觉目标：程序化示意、风格化产品还是接近实拍；是否需要外部模型、纹理和骨骼。
4. 探索方式：整机、特写、热点、配色、分解和讲解顺序。
5. 验证标准：真实浏览器截图、边界参数、装配穿插、桌面/手机以及错误日志。
6. 能力边界：明确区分可视化、运动学规则和真实物理求解。

两份网页实现说明均包含可复用的场景提示词。入口引导图来自实际运行截图，产品图与页面效果一致；不以生成图冒充已实现效果。

## 目前的边界

自行车的功率、气动和制动是演示估算或教学模型；升降椅没有气压、载荷、布料受力、人体平衡求解。乘坐滑行是预设路径，没有真实蹬地动作。脚轮的位移与转动关联不等于完整刚体物理模拟。

因此它们的价值是“看见一种实现方式并迁移到新对象”，而非证明某个真实产品的性能、舒适性或安全性。
